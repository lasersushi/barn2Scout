# Supabase: AI assistant backend

- `migrations/20261119000000_local_stand_in_schema.sql`: **local testing only.** Stand-ins for the tables the app already uses in the real project (profiles, scouting records, picklists, pit assignments). It runs only on a database with no `profiles` table, so it does nothing on the real project.
- `migrations/20261120000000_ai_assistant.sql`: the `profiles.ai_access` flag, the `ai_usage` and `ai_cache` tables, and the budget functions.
- `functions/ai/`: the Edge Function the app calls for every AI feature. It holds the Anthropic API key.
- `seed.sql`: test accounts and **sample** scouting data for a local stack. It's generated by `dart run tool/generate_local_seed.dart`; don't edit it by hand.

## Test locally (nothing touches the real project)

You need [Docker](https://docs.docker.com/get-docker/) running and the [Supabase CLI](https://supabase.com/docs/guides/local-development/cli/getting-started).

1. Start the local stack from the repo root. The first run downloads the Docker images and takes a few minutes. It applies both migrations and `seed.sql`.

   ```bash
   supabase start
   ```

   It prints an **API URL** (`http://127.0.0.1:54321`) and an **anon key** (`supabase status` shows them again). Studio, a web view of the local database, is at http://127.0.0.1:54323.

2. Make the local secrets file from the example and put an Anthropic API key in it. The example caps local spend at $2.

   ```bash
   cp supabase/functions/.env.example supabase/functions/.env.local
   ```

3. Serve the AI function locally. Leave this terminal open; it prints the function's logs.

   ```bash
   supabase functions serve ai --env-file supabase/functions/.env.local
   ```

4. Point a **debug** build of the app at the local stack. In `lib/core/config/app_config.dart`, which is gitignored, set:
   - `supabaseUrl`: `http://10.0.2.2:54321` on the Android emulator (that address is your computer, seen from the emulator), or `http://<your computer's LAN IP>:54321` on a real phone on the same Wi-Fi.
   - `supabaseAnonKey`: the anon key from step 1.

   Debug builds allow plain `http` for this (`android/app/src/debug/AndroidManifest.xml`); release builds don't. **Put the real values back before building anything for the team.** A build made with these values talks only to your computer.

5. Run the app (`flutter run`) and sign in with a test account. The password for all three is `barn2-local-test`:

   | Account | Sees in the app |
   |---|---|
   | `scout@priorypanther.com` | AI tab → Teams only, 20 summaries a day |
   | `ai-scout@priorypanther.com` | Teams, Match briefs and Chat, unlimited |
   | `admin@prioryca.org` | Everything, plus the AI review button on Teams → Picklist and Manage → AI access |

6. Point the app at the sample event: Settings → Event Key Override → `2026cacac` (CA District Contra Costa, 2026). The schedule and TBA stats are real. The scouting reports are made-up sample data: a few teams are deliberately scouted unlike their rating, to give the picklist review something to find. They sync onto the phone within a minute.

7. Try it out:
   - AI → Teams → a team → **Generate summary**.
   - Open the same team again and press the button: it should say it was free, and the `ai_usage` request count in Studio should not go up.
   - As the scout account, generate 20 summaries; the 21st should be refused.

Reset everything (database, accounts, sample data, usage) with `supabase db reset`. Stop the stack with `supabase stop`.

Every Claude request is real and billed to your Anthropic key, even locally. Cached answers are free.

## Deploying to the real project (later, not for testing)

**These steps change the production Supabase project.** Only do this when you're ready for the team to use AI.

1. `supabase link --project-ref <your-project-ref>`
2. `supabase db push`. The stand-in migration does nothing there (`profiles` exists); the AI migration adds the column, tables and functions.
3. `supabase secrets set ANTHROPIC_API_KEY=<key>`
4. `supabase functions deploy ai`
5. Check that every mentor's row in `profiles` has `role` set to `admin` or `super_admin`. The function reads admin status from there, not from the app's email lists.
6. If your Anthropic Console organization offers a spend limit, set one as a second safety net.

## Settings (function secrets / `.env.local`)

| Name | Default | Meaning |
|---|---|---|
| `ANTHROPIC_API_KEY` | (required) | Key the function calls Claude with |
| `AI_DAILY_LIMIT` | `20` | Generations per day for scouters without the AI role |
| `AI_MONTH_CAP_USD` | `20` | Team-wide spend per calendar month; everyone is refused past it |
| `AI_YEAR_CAP_USD` | `48` | Team-wide spend per calendar year |
| `AI_ALLOWED_EMAIL_DOMAINS` | `priorypanther.com,prioryca.org` | Non-admin accounts must be on one of these |

## Checking spend

```sql
select date_trunc('month', day) as month, sum(cost_usd) as usd, sum(requests) as requests
from ai_usage group by 1 order by 1 desc;
```

The function computes cost from each response's token counts and its price table (`functions/ai/policy.ts`). The Anthropic Console's usage page is the authoritative bill.
